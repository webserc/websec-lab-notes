# 第一部分：HTTP 到底是什么 ★

## 1.1 一句话

**浏览器和服务器之间，来回传的是一段文本。** 就这么简单。

你昨天所有的操作——访问页面、上传文件、改配置后验证——本质都是在发这段文本、收那段文本。

## 1.2 请求长什么样

```
POST /vulnerabilities/upload/ HTTP/1.1     ← 第一行：方法 路径 版本
Host: 127.0.0.1:4280                        ← 以下都是"头"
User-Agent: Mozilla/5.0
Content-Type: multipart/form-data; boundary=----xyz
Content-Length: 342
                                            ← 这里必须有一个空行
------xyz                                   ← 以下都是"体"
Content-Disposition: form-data; name="uploaded"; filename="shell.php"
Content-Type: application/x-php

<?php echo "PWNED:"; ?>
------xyz--
```

**拆成三块记：**

| 块 | 是什么 | 举例 |
|---|---|---|
| 第一行 | 我要干什么 | `POST /upload/` |
| 头（Headers） | 附带的说明 | `Host`、`Content-Type` |
| 体（Body） | 真正送过去的数据 | 你上传的文件 |

**关键：头和体之间必须有一个空行。** 没有它，服务器分不清哪儿是头哪儿是体。

## 1.3 响应长什么样

```
HTTP/1.1 200 OK                            ← 第一行：版本 状态码 短语
Server: Apache/2.4.69                      ← 头
Content-Type: text/html
Content-Length: 103
                                            ← 空行
<h1>PWNED:hello</h1>                        ← 体
```

结构一模一样，只是方向反过来。

## 1.4 两种方法：GET 和 POST

| | GET | POST |
|---|---|---|
| 数据放哪 | 在 URL 里（`?c=hello`） | 在体（Body）里 |
| 长度限制 | 有（URL 不能太长） | 基本没有 |
| 能不能传文件 | 不能 | 能 |
| 会不会被记录 | 会（在浏览器历史、服务器日志里） | 一般不 |

**昨天你用的 `?c=hello` 就是 GET 传参。**

**上传文件必须是 POST**，因为文件得放在体里。

# 第二部分：状态码，服务器在说什么 ★

## 2.1 五位族，先记这五类

| 开头 | 意思 | 一句话 |
|---|---|---|
| `2xx` | 成功 | 办好了 |
| `3xx` | 跳转 | 不在我这儿，去别处 |
| `4xx` | 你的错 | 请求有问题 |
| `5xx` | 我的错 | 服务器崩了 |

## 2.2 昨天你见过的几个

| 码 | 名字 | 你昨天在哪遇到 |
|---|---|---|
| `200` | OK | `shell.php` 执行成功、`shell.php5` 返回源码 |
| `302` | Found（跳转） | 登录成功后跳到 `index.php` |
| `404` | Not Found | 文件不在那个路径 |
| `401` | Unauthorized | 前天 lab 里伪造失败那次 |
| `403` | Forbidden | 有权限检查但你不被允许 |

## 2.3 最容易搞混的一对 ★

**`404` 和 `403` 的区别：**

`403` = 这个文件**在**，但**不让你看**。

`404` = 这个文件**压根不存在**（或者服务器故意装作不存在）。

**为什么这对你重要：** 你昨天 `.php5` 拿到 404，第一反应以为"文件不在"。其实当时是缓存骗了你，用 curl 一测就是 200。

**判断方法：永远用 curl 拿真实状态码，别信浏览器。**

```bash
curl -o /dev/null -w "%{http_code}\n" "http://127.0.0.1:4280/某个路径"
```

## 2.4 `200` 不代表成功 ★

这条要重点记。

你昨天访问 `shell.php5` 拿到的是 **200**，但返回的是源码，**代码没执行**。

**所以：状态码只看"请求有没有被处理"，不看"处理得对不对"。**

判断 PHP 有没有执行，只能看**响应体内容**——有没有 `PWNED`，还是把 `<?php` 原样吐出来了。

# 第三部分：Apache 的配置体系 ★

## 3.1 为什么配置要分那么多目录

因为一个 Apache 能干很多事：支持 HTTPS、跑 PHP、限制目录、做反向代理……全写在一个文件里会乱成一锅粥。

所以它拆成模块，每个模块一个文件。

**三个关键目录：**

| 目录 | 作用 | 类比 |
|---|---|---|
| `mods-available` | 所有可用的模块，装了但没开 | 仓库里的零件 |
| `mods-enabled` | 已启用的模块（都是软链接） | 装到机器上的零件 |
| `conf-available` | 所有可用的配置片段 | 写好的说明书 |
| `conf-enabled` | 已启用的配置片段（也是软链接） | 贴在机器上的说明书 |

**你昨天改的那个文件：**

```
/etc/apache2/conf-available/docker-php.conf
```

它在 `conf-available` 里，说明它已经是"被启用的配置"了（`conf-enabled` 里有一个指向它的链接）。

## 3.2 改动为什么要 graceful

因为 Apache 启动时会把配置**全部读进内存**。你改了磁盘上的文件，内存里那份还是旧的。

`graceful` 就是让它**重新读一遍**。

**为什么不用 `restart`：** restart 会把正在处理的请求全部掐断，用户可能正好在上传一个大文件，就失败了。`graceful` 是等手上的活干完再换配置。

## 3.3 怎么查"某个功能是谁配的"

```bash
grep -rn "关键词" /etc/apache2/
```

参数含义：

| 参数 | 意思 |
|---|---|
| `-r` | 递归，子目录也搜 |
| `-n` | 显示行号 |
| `（关键词）` | 要搜的字符串 |

**你昨天就是靠这一条从"为什么不执行"挖到"因为 `FilesMatch` 只认 .php"。**

**这个套路要记住：遇到"为什么不行"，先 grep 配置，别猜。**

# 第四部分：正则，只要六个符号

## 4.1 为什么必须学一点

你昨天看到 `\.php$` 一脸懵。这不是英语问题，是正则语法。

**只要记六个符号，就能读懂 90% 的配置。**

## 4.2 六个符号

| 符号 | 意思 | 例子 |
|---|---|---|
| `.` | 任意一个字符 | `a.c` 匹配 `abc`、`a1c` |
| `\.` | 真正的点号 | `\.php` 匹配 `.php` |
| `$` | 结尾 | `php$` 必须以 php 结尾 |
| `^` | 开头 | `^php` 必须以 php 开头 |
| `*` | 前面那个出现 0 次或多次 | `ab*c` 匹配 `ac`、`abc`、`abbbc` |
| `?` | 前面那个出现 0 次或 1 次 | `php5?` 匹配 `php`、`php5` |

## 4.3 把昨天那行读懂

```
<FilesMatch \.php$>
```

一个字符一个字符读：

- `\.` = 真正的点号
- `php` = 字母 p、h、p
- `$` = 必须到这里结束

连起来：**「点号 + p + h + p，然后结束」**。也就是「文件名以 `.php` 结尾」。

**为什么 `.php5` 不匹配：** 因为它结尾是 `5`，不是"结束"。`$` 要求后面什么都没有。

## 4.4 你改成了什么

```
<FilesMatch \.php5?$>
```

`5?` = 这个 5 可以有，也可以没有。

所以：`.php` 匹配（没有 5），`.php5` 也匹配（有 5）。

**`.php55` 呢？** 不匹配——因为 `5?` 只允许一个 5。

**`.phtml` 呢？** 也不匹配——里面有 t、m、l 三个字母，规则里没有。

这就是为什么改完之后 `.php` 和 `.php5` 都能跑，别的还是不行。

# 第五部分：Linux 命令，够用就行

## 5.1 昨天用过的

| 命令 | 干什么 |
|---|---|
| `ls -l` | 列文件，带详细信息（权限、大小、时间） |
| `cat` | 显示文件全部内容 |
| `grep` | 在文件里搜字符串 |
| `cp` | 复制 |
| `cd` | 换目录 |
| `echo` | 输出一段文字（也用来写文件） |

## 5.2 `grep` 的三个常用参数

```bash
grep -rn "FilesMatch" /etc/apache2/
```

| 参数 | 意思 |
|---|---|
| `-r` | 递归搜子目录 |
| `-n` | 显示行号 |
| `-o` | 只输出匹配到的部分（不整行） |

**`-o` 你昨天也用过：**

```bash
grep -oP "name='user_token' value='\K[^']+"
```

`-P` 是启用更高级的正则，`\K` 是"前面的别看，从这里开始算"，`[^']+` 是"一串不是单引号的字符"。

**这一条现在看不懂没关系**，记住它的作用就行：**从 HTML 里抠出 CSRF token 的值**。

## 5.3 管道 `|`

**一句话：** 把前一个命令的输出，当成后一个命令的输入。

**类比：** 流水线。第一个人削皮，把苹果往后传，第二个人切块。

```bash
curl -s http://... | grep -oP "user_token' value='\K[^']+"
```

读作：先 curl 拿到页面，把页面交给 grep，grep 从里面抠出 token。

## 5.4 `-o /dev/null -w`

```bash
curl -o /dev/null -w "%{http_code}\n" "http://..."
```

| 部分 | 意思 |
|---|---|
| `-o /dev/null` | 把响应内容丢进黑洞，不显示 |
| `-w "%{http_code}"` | 只打印状态码 |

**`/dev/null` 是 Linux 的黑洞**——写进去的东西直接消失。

**这个组合是拿来"只问状态码，不要内容"的。** 你昨天用它验证 `.php5` 返回 200 还是 404。

# 第六部分：把这些串起来

## 6.1 昨天那一晚，用新的语言重讲一遍

你访问 `http://127.0.0.1:4280/hackable/uploads/shell.php5?c=working`：

1. 浏览器发出 **GET** 请求，路径是 `/hackable/uploads/shell.php5`，参数 `c=working` 在 URL 里
2. 请求打到 Kali 的 **4280** 端口，经**端口映射**转到容器的 **80**
3. Apache 收到，先看 `<FilesMatch>` 规则
4. 文件名 `shell.php5` 在改动前不匹配 `\.php$`，所以**没交给 PHP**
5. Apache 把它当成普通文件，**原样读出内容**发回去
6. 状态码 **200**，响应体就是那 37 字节的源码
7. 你在改动后重试，这次匹配上了 `\.php5?$`，交给了 PHP
8. PHP 执行，输出 `PWNED:working`，状态码还是 **200**

**注意第 6 步和第 8 步：状态码都是 200，但一个是源码，一个是执行结果。**

这就是"200 不代表成功"。

## 6.2 一个判断口诀

**遇到"为什么不对"，按这个顺序查：**

1. **请求发对了吗** → 看浏览器 F12 的 Network，或者 curl 一遍
2. **状态码是什么** → 4xx 是请求问题，5xx 是服务器问题，2xx 要再看内容
3. **内容对不对** → 200 也可能是错的
4. **服务器怎么处理的** → grep 配置，看规则
5. **规则为什么这样** → 读那个正则

**五步走完，一般就到底了。**
