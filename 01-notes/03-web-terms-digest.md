# 第一组：昨天直接卡住你的五个（最急）

## 1. FilesMatch

**一句话：** Apache 的一条规则，用来说「哪些文件名的文件，按什么方式处理」。

**类比：** 保安站在门口，手里拿一张纸写着"只放这三种证件的人进来"。`FilesMatch` 就是那张纸。

**昨天在哪见过：** 改的那一行就是它。

```
<FilesMatch \.php$>
```

---

## 2. SetHandler

**一句话：** 告诉 Apache「命中上面那条规则的文件，交给谁来处理」。

**类比：** 保安放人进来之后，还得说一句"这个交给三楼的部门"。`SetHandler` 就是"交给三楼"。

**昨天在哪见过：**

```
SetHandler application/x-httpd-php
```

意思是「交给 PHP 处理」。

---

## 3. 正则里的 `\.` 和 `$`

**一句话：** 在正则里，`.` 是「任意一个字符」，要表示真正的点号，得写成 `\.`；`$` 表示「结尾」。

**类比：** `.` 像扑克里的"万能牌"，能代表任何一张。你想真的打出一张"点号"，就得给它加个反斜杠变成 `\.`。

**昨天在哪见过：**

```
\.php$
```

读作：「点、p、h、p，然后必须结束」。也就是「文件名必须以 `.php` 结尾」。

**所以：** `.php5` 不匹配（结尾是 5，不是结束），`.php` 匹配。

---

## 4. graceful（`apache2ctl -k graceful`）

**一句话：** 让 Apache 重新读一遍配置，但**不打断正在处理的请求**，慢慢切换过去。

**类比：** 换班，不是立刻把所有客人赶出去重开，而是等手上这单做完再交班。所以叫"优雅"。

**昨天在哪见过：**

```bash
docker exec dvwa-dvwa-1 apache2ctl -k graceful
```

改完配置必须跑这条，不然改动不生效。

**对比：** `restart` 是直接断掉重来，`graceful` 是等一等再换。

---

## 5. `curl -F`

**一句话：** 让 curl 用 **multipart 表单**的方式发请求，专门用来传文件。

**类比：** `-d` 是发一条短信（纯文本），`-F` 是寄一个快递包裹（可以装文件）。

**昨天在哪见过：**

```bash
curl -F "uploaded=@/tmp/shell.php5;type=image/jpeg" http://...
```

拆开看：
- `uploaded=` 表单字段名
- `@` 读本地文件
- `;type=` 假装这个文件是 jpeg

**这就是「改 MIME」这一步。**

# 第二组：上传请求本身的骨架（午饭抄）

## 6. multipart

**一句话：** 一个请求里同时装好几段内容时的打包方式。

**类比：** 一个快递箱里分好几个格子，每格装不同的东西，箱子外面贴一张总清单。

**昨天在哪见过：** 浏览器上传文件时自动用的就是它。

`Content-Type: multipart/form-data`

---

## 7. boundary

**一句话：** 打包时用来分隔每一段的"胶带"，一段字符串，前后必须一致。

**类比：** 每格之间贴一条印着同样编号的封条。开箱时按编号找格子。

**昨天在哪见过：**

```
------WebKitFormBoundary7MA4YWxkTrZu0gW
```

**关键：** 这个字符串也是浏览器或攻击者自己生成的，改它服务器也认。

---

## 8. Content-Disposition

**一句话：** 每一段开头的一行说明，写清楚「这格叫什么名字、文件名是什么」。

**类比：** 每个格子外面贴的小标签：「本格 = 头像，文件名 = test.jpg」。

**昨天在哪见过：**

```
Content-Disposition: form-data; name="file"; filename="test.jpg"
```

**为什么重要：** `filename` 就在这里，**它是客户端写的，服务器不能全信**。

---

## 9. Content-Type

**一句话：** 说明"这段内容是什么类型"。

**注意有两个地方都有它：**

一是请求头的 `Content-Type`，说的是整个请求的格式（`multipart/form-data`）。

二是每一段里的 `Content-Type`，说的是这一格的内容类型（`image/jpeg`）。

**关键：** 段内那个是客户端写的，**跟文件真实内容没有关系**。所以"改 MIME 绕过"改的就是它。

---

## 10. magic bytes（文件头魔数）

**一句话：** 文件最开头那几个字节，是文件的"身份证号"，改不了。

| 格式 | 开头是什么 |
|---|---|
| GIF | `GIF89a`（就是这六个字母） |
| JPEG | `FF D8 FF` |
| PNG | `89 50 4E 47` |

**类比：** 后缀是身份证上的名字，谁都能改；magic bytes 是 DNA，改不了。

**所以严谨的检测读 magic bytes，不读后缀。**

**怎么绕：** 文件开头塞 `GIF89a`，后面接 php 代码。

# 第三组：攻击侧的词（下午抄）

## 11. payload

**一句话：** 真正要执行的那部分内容。

**类比：** 炸弹里真正起作用的那块药，外壳怎么包都无所谓。

**昨天在哪见过：** `<?php echo "PWNED:"; ?>` 就是 payload。

---

## 12. webshell

**一句话：** 传到服务器上、能让你远程执行命令的一段网页代码。

**类比：** 在别人家门上偷偷装了一把只有你有钥匙的锁。

---

## 13. 一句话木马

**一句话：** 最短的 webshell，只有一行。

```php
<?php system($_GET['c']); ?>
```

访问 `shell.php?c=whoami` 就执行了 `whoami`。

**注意：** 这是真木马，威力比昨天用的 `echo` 大得多。在靶场里练可以，别乱用。

---

## 14. 反弹 shell

**一句话：** 让被攻击的机器主动连回你的机器，把命令行交给你。

**类比：** 目标在内网，你进不去，只能让它自己走出来找你。

**为什么叫"反弹"：** 连接方向是反的——从目标连向你，不是你连向目标。

# 第四组：防护侧的词（下午抄）

## 15. 白名单 / 黑名单

**一句话：**

黑名单 = 明确禁止哪些（`.php` 不行、`.jsp` 不行）

白名单 = 明确只允许哪些（只许 `.jpg` `.png` `.gif`）

**类比：** 黑名单是"这些人不许进"，白名单是"只许这几个进"。

**为什么白名单更安全：** 黑名单永远列不全——你知道 `.php` 危险，但 `.php5`、`.phtml`、`.phar` 呢？

**昨天在哪见过：** DVWA 的 Medium 开始用黑名单，High 用白名单。

---

## 16. 二次渲染

**一句话：** 服务器收到图片后，用图像库**重新压一遍**再保存，你藏在文件里的代码会被丢掉。

**类比：** 你在一张照片背面写了字，对方拿去重新洗了一张，只留正面——你写的字没了。

**为什么它是最强防护：** 因为它不看你传了什么，只看图像本身。

**绕过方向：** 找"重新压完还保留的区域"，比如 EXIF（照片元数据，存拍摄时间、机型那些）。

---

## 17. 图像马

**一句话：** 一张能正常打开的图片，尾部藏了一段 php 代码。

**做法：**

```bash
cat 1.jpg shell.php > shell.jpg
```

**效果：** 检测读文件头看到 JPEG，放行；服务器执行时 PHP 把前面一堆图片数据当文本输出，最后执行你那段代码。

**注意：** 遇到二次渲染就失效。

---

## 18. 解析漏洞

**一句话：** 服务器对"这个文件该不该执行"判断错了。

**三种最常见：**

**Apache 多后缀** `shell.php.jpg` —— Apache 按点切开看每一段，发现有 `.php` 就当 PHP 执行。白名单只看最后一个 `.jpg`，放行了。

**Nginx 畸形解析** `/upload/shell.jpg/x.php` —— Nginx 找不到 `x.php` 就交给 PHP，PHP 往前找到真实存在的 `shell.jpg` 执行了。

**IIS 分号** `shell.asp;.jpg` —— IIS6 把分号当参数分隔，实际执行 `shell.asp`。

**一句话记：** 服务器对文件名的理解，和你以为的不一样。

# 第五组：环境和工具（有余力再抄）

## 19. 镜像 / 容器

**一句话：**

**镜像** = 一个装好系统的压缩包（比如"装好 DVWA 的整个系统"）。

**容器** = 用这个压缩包跑起来的一个实例。

**类比：** 镜像是"菜谱 + 所有食材"，容器是"按这个菜谱实际做出来的那一盘菜"。一盘菜倒了，菜谱还在，能再做一盘。

---

## 20. `docker compose`

**一句话：** 用一个配置文件一次管好几个容器。

**昨天在哪见过：** DVWA 的 compose 版起了两个容器——一个是网站，一个是数据库。所以是"两个容器一起管"。

```bash
cd ~/DVWA
docker compose ps        # 看状态
docker compose up -d     # 启动
docker compose down      # 全停
```

---

## 21. `docker exec`

**一句话：** 在**正在运行的容器里**执行一条命令，不用先"进去"。

**类比：** 不用进门，从窗口把手伸进去拿个东西。

**昨天在哪见过：**

```bash
docker exec dvwa-dvwa-1 ls -l /var/www/html/hackable/uploads/
```

`dvwa-dvwa-1` 是容器名，后面是要在容器里跑的命�令。

---

## 22. 端口映射

**一句话：** 把宿主机（Kali）的某个端口，转发到容器里的某个端口。

**写法：** `宿主机端口 : 容器内端口`

**昨天在哪见过：**

```
0.0.0.0:4280->80/tcp
```

意思：Kali 的 **4280** 端口，转到容器里的 **80** 端口。

所以你在浏览器访问 `127.0.0.1:4280`，实际打到的是容器里的 80。

**昨天为什么卡这么久：** 你以为是 80 或 8080，实际映射到 4280。

## 第一件：证明「文件在不在」比「猜」快

```bash

```

答案：说明上传就没成功，跟解析无关。

## 第二件：证明「后缀」和「解析」是两回事

访问 `shell.php`，记下状态码和内容。

访问 `shell.php5`，记下状态码和内容。

两个都记下来，对比。

## 第三件：把配置改回去，再改回来

先改回 `\.php$`，graceful，访问 `.php5`（应该又变回源码）。

再改成 `\.php5?$`，graceful，访问（应该又能执行）。

**做这一步的意义：** 你会亲眼看到"规则决定行为"，而不是"文件决定行为"。
