# 第一部分：昨晚到底做出了什么

## 一条完整的因果链

```
传 shell.php   → 执行成功（PWNED:hello）
传 shell.php5  → 上传成功、访问 200、但返回源码
读配置         → 发现 <FilesMatch \.php$>
改配置         → <FilesMatch \.php5?$>
graceful       → 重新加载
再访问 php5    → 执行成功（PWNED:working）
```

**这条链的价值不在结果，在于你验了四件事：**

| 验了什么 | 结果是 | 说明 |
|---|---|---|
| 上传目录能不能执行 | 能 | `.php` 生效 |
| 后缀和解析是不是一回事 | 是两回事 | `.php5` 传上去了但不执行 |
| 谁决定"执不执行" | 配置 | `<FilesMatch>` 那一行 |
| 改配置有没有用 | 有用 | `.php5` 从源码变成执行 |

## 一句结论

**决定一个文件能不能执行，不是文件名，是服务器配置。**

文件名只是让配置去匹配的字符串。你昨天改的不是文件，是"匹配规则"。

# 第二部分：三个昨天没讲透的机制

## 机制一：Apache 为什么"多后缀"会执行（新）

昨天只提了 `shell.php.jpg` 可能被执行，没讲原因。

**原理：**

Apache 有个指令叫 `AddHandler`，写法是：

```apache
AddHandler application/x-httpd-php .php
```

它的匹配方式和 `FilesMatch` **完全不同**：

| | `FilesMatch` | `AddHandler` |
|---|---|---|
| 看什么 | 整个文件名，用正则匹配 | 把文件名按 `.` 切开，逐段比对 |
| `shell.php.jpg` | 不匹配（结尾是 jpg） | **匹配**（第二段是 php） |

**所以：**

`FilesMatch` 严格 → `.php5` 不行

`AddHandler` 宽松 → `shell.php.jpg` 反而行

**这就是为什么"多后缀解析漏洞"只在用 `AddHandler` 的老配置上成立。**

你昨天那台用的是 `FilesMatch`，所以多后缀那招**根本不适用**——这解释了为什么教程里那招你没试成。

## 机制二：`.htaccess` 为什么能废掉白名单（新）

**一句话：** `.htaccess` 是 Apache 的"目录级配置"，放在哪个目录就管哪个目录。

**为什么这是大杀器：**

假设白名单只允许 `.jpg`。你传不上 `.php`。

但你传一个**名字叫 `.htaccess` 的文件**（它以 `.` 开头，通常没有后缀，白名单经常漏掉它），里面写：

```apache
AddType application/x-httpd-php .jpg
```

**这一行的意思是：从这个目录开始，所有 `.jpg` 都当 PHP 处理。**

于是你再传 `shell.jpg`（内容是 php），它就会执行。

**一句话记：白名单管的是"文件后缀"，`.htaccess` 改的是"后缀怎么解释"。你在管名字，它改规则。**

**前提条件（三个都要满足）：**

1. Apache 允许 `AllowOverride`（默认很多配置里是开的）
2. 上传目录里放得进 `.htaccess`
3. 白名单没拦 `.htaccess`（新手常漏）

## 机制三：为什么"改配置"这招在真实环境不能用（新·重要）

**你昨天是作弊看答案。**

你能改 `FilesMatch`，是因为服务器是你的。真实目标上，你没有 root，改不了任何配置。

**那怎么办？换思路：**

```
你能改的：传什么文件名
服务器定的：哪些后缀会被执行
```

**所以真实环境里的动作是：枚举。**

试这些后缀，看哪个能执行：

```
.php     ← 首选
.php5    ← 老版本 PHP
.php4
.php3
.phtml   ← 很常见
.phar    ← PHP 归档格式，有时能执行
.phps    ← 显示源码用
.pht
.inc
.php.jpg ← 多后缀（AddHandler 环境有效）
.php.    ← Windows 末尾点号
```

**每个都传一次，看返回的是源码还是执行结果。**

**这一步的本质，和你昨天做的事一模一样——只是你不能改规则，只能撞规则。**

# 第三部分：拿到一个上传点，怎么一步步判断

> 这张表是新的。以后遇到任何上传点，从上往下走。

## 第一步：文件传上去了吗

**先看服务器上有没有。**

```bash
docker exec 容器名 ls -l /路径/uploads/
```

**不在** → 上传这一步就失败了，问题在请求或前端，别往下想。

**在** → 继续。

## 第二步：能访问吗

```bash
curl -o /dev/null -w "%{http_code}\n" "http://目标/路径/shell.php"
```

**404** → 路径不对或文件名被改，去响应里找真实路径。

**403** → 文件在但被拒，可能是目录禁执行或 WAF。

**200** → 继续。

## 第三步：执行了吗

```bash
curl -s "http://目标/路径/shell.php?c=hello"
```

**显示 `PWNED:hello`** → 执行了，成了。

**显示 `<?php echo ...`** → 没执行，被当静态文件。

**什么都不显示** → 可能是空白页，用 `curl -i` 看状态码和头。

## 第四步（如果没执行）：换后缀重试

按第二部分那个清单一个个试。

## 第五步（如果全不行）：找旁路

| 情况 | 出路 |
|---|---|
| 目录禁执行 | 改用文件包含（LFI）去包含它 |
| 白名单很严 | 试 `.htaccess`（前提是 Apache） |
| 名字被随机化 | 从响应里读回文件名；或用竞争条件 |
| 有二次渲染 | 转向图片马 + EXIF |

## 这张表的意义

**它把"试"变成了"排查"。**

你昨天从第一步一路走到第四步，今天这张表只是把它写下来——以后遇到新的上传点，不用重新想。

# 第四部分：DVWA 四档难度各加了什么

> 明天晚上要用。**先看这表，再去打，就不会瞎试。**

## Low

**加了什么检测：** 什么都没加。

**哪招有效：** 全部。

**这一档练的是：** 确认基础流程能走通。你昨晚已经过了。

## Medium

**加了什么：**

1. 检查后缀是不是在**黑名单**里（`php`、`exe` 等）
2. 检查 MIME 是不是 `image/jpeg` 或 `image/png`
3. 检查文件大小不超过 100KB

**哪招有效：**

改后缀成 `.php5`（不在黑名单里），同时把段内 `Content-Type` 写成 `image/jpeg`。

**注意：** 你昨天验过——`.php5` 在你这台环境**不能执行**。所以 Medium 这关，改后缀这招在你这台机器上**可能过不了**。

**那怎么办：** 试 `.phtml`。它在很多 `FilesMatch` 配置里。

**这一档练的是：** 黑名单永远列不全——你自己去补全它还漏了哪个。

## High

**加了什么：**

1. 后缀必须是白名单（只有 jpg/jpeg/png）
2. `getimagesize()` 检查——它会读文件头判断是不是真图片
3. 文件大小限制

**哪招有效：**

**图像马。** 文件头塞 `GIF89a` 或真 JPEG 头，后面接 php。

`getimagesize()` 只看文件头，看到它是图片就放行。

**这一档练的是：** "检查文件类型"和"检查文件内容"是两件事。前者能被伪造，后者不能。

**做完记得从服务器下载回来，用 `xxd` 看看你的 payload 还在不在。** 这是 High 和 Impossible 的分界线。

## Impossible

**加了什么：**

1. 白名单 + 严格校验
2. **二次渲染**（用 GD 库重新压一遍）
3. 随机文件名 + 完整路径存储
4. 上传目录禁执行

**为什么无解：**

二次渲染会把你在文件里塞的一切丢掉，只保留图像像素。

随机文件名让你没法知道访问路径。

目录禁执行让你就算知道路径也跑不起来。

**这一档不是让你破解的，是让你看懂"防护做全了长什么样"。**

**能做到说清「为什么无解」，比硬凑一个 payload 更有价值。**

# 第六部分：明天晚上的验证题（全新的）

> 不是重复昨天的，是往下走一步。

## 题一：验证"FilesMatch 严格，AddHandler 宽松"

在容器里看这个配置是不是存在：

```bash
docker exec dvwa-dvwa-1 grep -rn "AddHandler" /etc/apache2/
```

**如果一条都没有** → 说明你这台只用 `FilesMatch`，所以多后缀那招彻底不适用。记下来。

**如果有输出** → 看它绑定了哪些后缀，那才是真正能绕的。

## 题二：枚举后缀，看哪个能执行

传这几个（每个都带同样的 php 内容）：

```
shell.phtml
shell.phar
shell.pht
shell.php4
```

每个传完都访问一次，记下：**执行了 / 返回源码 / 404**。

**这一题的意义：** 你在真实环境里唯一能做的事，就是把这一列试完。今天先在自己机器上试一遍，熟悉流程。

## 题三：切到 Medium，看黑名单拦了什么

DVWA Security 改成 Medium，再传 `shell.php`。

**看它返回什么提示。** 然后把提示原文记下来——那就是黑名单的报错。

再传 `shell.phtml`，看能不能过。

**这一题的意义：** 你会亲眼看到"黑名单"长什么样，以及它为什么拦不全。
